## 1. 概述

设计 BOM 与 PLM/ERP BOM **以文件形式导入**（Phase 1 不做系统直连）后自动核对：按料号+层级对齐，检查数量/版本/新增/缺失/替代料/状态（PRD §20）；差异带风险分级与 AI 归因；逐条人工处置并可转整改任务。验收 KPI：BOM 核对时间 ↓ ≥ 70%。

## 2. Feature Units

### F6.1 BOM导入与列映射

- **FR6.1.1** 文件：`xlsx/xls/csv` 为主；PDF 表格经 F1 解析后按表导入。
- **FR6.1.2** 导入向导：解析表头 → 系统自动猜测列映射（表头语义匹配）→ 人工调整确认。目标列：`料号 / 名称 / 数量 / 层级 / 版本 / 替代料 / 状态 / 单位`。
- **FR6.1.3** 必选列：料号、数量；其余可选（缺失列对应检查项自动跳过并在运行信息中说明）。
- **FR6.1.4** 行级校验：料号为空、数量非正数值、层级格式非法 → 汇总为可修正的错误列表，修正后重新校验；错误行不进入比对。
- **FR6.1.5** 列映射模板可保存复用（按模板名），下次导入一键应用。
- **AC6.1.1** 一个含 500 行、2 列名非常规的 BOM，用户在映射页 2 分钟内完成映射（易用性验收，走查）。

### F6.2 对齐与核对引擎

- **FR6.2.1** 对齐键：料号；提供层级列时按 `层级路径+料号` 对齐（同名料号在不同层级视为不同对象）。
- **FR6.2.2** 核对项（PRD §20）：`数量不一致 / 版本不一致 / A新增 / B缺失 / 替代料不一致 / 状态不一致`；双方一致的料号计入"一致"。
- **FR6.2.3** 替代料逻辑：料号 X 在对方 BOM 缺失，但 X 出现在对方某行替代料列 → 判"替代料差异"而非"缺失"。
- **FR6.2.4** 数值比较：数量支持单位换算（单位列存在且可换算时）；版本比较为字符串精确比对。
- **AC6.2.1** 构造差异集（每类差异 ≥5 条，含替代料嵌套场景）导入，核对引擎结果与预置答案 100% 一致。

### F6.3 差异风险分级 + AI 分析

- **FR6.3.1** 规则矩阵（可配置）默认：版本不一致 → 高；数量不一致 → 中（安全件/关键件清单命中 → 高）；新增/缺失 → 中；替代料 → 中；状态 → 低。
- **FR6.3.2** AI 归因建议：结合两 BOM 的文件名/版本时间/备注列生成一句归因（如"PLM 版本未更新，请确认是否漏改"），仅建议性质，标注 [AI]。
- **FR6.3.3** 每条差异显示：差异类型、风险等级、两侧值对照、AI 归因。

### F6.4 比对总览

- **FR6.4.1** 总览卡片（UI 页面12）：总物料数 / 一致 / 差异 / 风险分布（高中低）；支持点击钻取到对应明细筛选。
- **FR6.4.2** 明细表支持按 差异类型 / 风险等级 / 处置状态 筛选与排序。

### F6.5 差异逐条人工处置

- **FR6.5.1** 处置动作：`确认（认可差异合法）/ 忽略 / 转整改任务`；转整改任务创建 `Issue` 对象并关联差异行（字段：标题、描述含差异快照、责任人、截止日期）。
- **FR6.5.2** 支持按当前筛选结果批量处置（逐条记录处置人）。
- **FR6.5.3** 处置记录：处置人、时间、可选意见；处置可撤销（撤销亦入审计）。
- **FR6.5.4** 全部差异处置完毕后，比对运行可执行"完成确认"（F10.2 定版）；定版后明细锁定。
- **AC6.5.1** 转整改任务的差异，在整改任务列表可见且双向链接可跳转。

### F6.6 比对报告导出

- **FR6.6.1** PDF / Excel / Word 三格式；内容：总览、差异明细（含等级/AI归因）、处置记录、运行信息（文件、版本、时间、操作人）。
- **FR6.6.2** `DRAFT` 态导出带草稿水印。

## 3. 数据模型（核心）

| 实体 | 关键字段 |
| ---- | ---- |
| `bom` | id, project_id, side(design/plm), source_file, version_label, column_mapping(JSONB), row_count |
| `bom_row` | bom_id, part_no, name?, qty, level_path?, version?, substitutes[]?, status?, unit? |
| `bom_diff_run` | id, project_id, bom_a, bom_b, status(F10.2), overview(JSONB), created_by |
| `bom_diff_item` | run_id, part_no, level_path?, diff_type, risk(高/中/低), value_a, value_b, ai_note?, disposition(none/confirmed/ignored/issue), issue_id?, disposed_by/at, note? |

## 4. API 概要

```
POST /api/v1/boms/import                # 上传+列映射（两步）
POST /api/v1/bom-diff/runs              # 发起比对（异步）
GET  /api/v1/bom-diff/runs/{id}         # 总览
GET  /api/v1/bom-diff/runs/{id}/items   # 明细（筛选）
POST /api/v1/bom-diff/items/{id}/dispose    # 处置（confirm/ignore/to_issue）
POST /api/v1/bom-diff/runs/{id}/confirm     # 完成确认（F10.2）
POST /api/v1/bom-diff/runs/{id}/export  # pdf/excel/word
```

## 5. 横切接入（F10）

- **状态机**：比对运行 `DRAFT（比对完成可处置）→ APPROVED（完成确认，锁定）`。
- **审计**：`bomdiff.run / item.disposed / item.disposal.revoked / run.confirmed`；AI 归因记录 prompt 版本。
- **KPI**：`bomdiff.start → bomdiff.confirm` 耗时（对照人工基线，验收 ↓70%）；处置耗时分布。
- **对象模型**：转整改任务创建的 `Issue` 进入统一 Issue 对象（F9.6、知识库质量问题分类复用同一模型）。

## 6. 非目标

与 PLM/ERP 系统直连或回写提交（第二阶段，PRD 明确）[PHASE1_SPEC §4]；多楼层 BOM/制造 BOM 变形（MBOM）比对；单价成本比对。

## 7. 开放问题

- **Q1** 安全件/关键件清单来源（质量部提供初版清单，决定数量差异升"高"的规则）。
- **Q2** 替代料列的解析约定（分隔符、多替代料、替代组）需样例数据确认。
- **Q3** 是否需要同一 BOM 历史多次比对的版本留存与 diff-of-diff（建议 Phase 1 只保留最近 N 次）。
