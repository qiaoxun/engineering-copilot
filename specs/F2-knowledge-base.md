## 1. 概述

企业工程文档统一存储与分类管理（PRD §35 的 Phase 1 子集）。每份文档可追溯来源、上传人、版本历史；全部组件支持私有化部署，数据不出企业域。

## 2. Feature Units

### F2.1 文档上传与版本管理

- **FR2.1.1** 支持单个/批量上传（单批 ≤50 个文件）；批量中单个失败不影响其余，结束后给逐文件结果汇总。
- **FR2.1.2** 去重：入库前计算 SHA-256 与全库比对；完全相同内容 → 提示"该文件已存在（文档名/版本/上传人）"，允许跳过或仍作为新关联上传。
- **FR2.1.3** 同名不同内容 → 弹出选择："上传为新版本"（版本号 +1，历史保留）或"作为独立文档"。
- **FR2.1.4** 版本历史展示：版本号、上传人、上传时间、文件大小、变更说明（选填）。
- **FR2.1.5** 删除为软删除；文档被 FMEA/报告等对象引用时，删除需展示引用方列表（是否禁止删除见 Q2）。
- **AC2.1.1** 同一文档上传 v1、v2 后，历史页可见两个版本且 v1 仍可查看。
- **AC2.1.2** 重复上传相同文件时去重提示出现且内容正确。

### F2.2 分类体系

- **FR2.2.1** 固定 7 个顶级分类：产品 / 设计 / BOM / FMEA / 测试 / 质量 / SOP（对齐 UI 页面22 左侧树）；Phase 1 不允许新建顶级分类。
- **FR2.2.2** 顶级下允许自定义子分类，树深度 ≤3。
- **FR2.2.3** 每份文档必须归属 ≥1 个分类；支持多分类。

### F2.3 文档与项目、产品关联

- **FR2.3.1** 文档 ↔ 项目：多对多；文档 ↔ 产品：多对一（可为空）。
- **FR2.3.2** RAG 引用、AI 推荐（F2.5）、生成类功能的输入勾选均依赖此关联，关联缺失的文档不参与项目维度推荐。

### F2.4 全文搜索与筛选

- **FR2.4.1** 全文检索（含中文分词）+ 组合筛选：分类 / 项目 / 时间范围 / 标签 / 上传人。
- **FR2.4.2** 结果列表命中片段高亮；支持按相关度、更新时间排序。
- **FR2.4.3** 搜索结果仅包含当前用户有权限可见的文档（权限过滤在查询层生效，而非前端隐藏）。

### F2.5 最近更新与 AI 推荐知识

- **FR2.5.1** 首页"最近更新"：当前用户可见范围内的最近 N 条文档变更。
- **FR2.5.2** AI 推荐：基于当前项目上下文（项目关联文档的向量表示 + 项目基本信息）检索相关历史案例文档 top-N，展示为"与当前项目相关的历史案例 N 个"。
- **FR2.5.3** 每条推荐附推荐理由（与项目中哪份文档/哪个主题相关）并可点击进入文档详情。
- **AC2.5.1** 为含"密封结构"文档的项目推荐出其他项目的密封失效案例文档（金标场景抽验）。

### F2.6 文档权限继承与私有化部署

- **FR2.6.1** 文档可见性默认继承其关联项目的成员/部门规则（Casbin domain 模型）；支持"全公司可见"标记覆盖。
- **FR2.6.2** 私有化部署检查表：LLM、嵌入、OCR、存储全部本地组件，构建产物不含任何外呼依赖；交付时随附《外呼清单=空》自检报告。
- **AC2.6.1** 无项目权限的用户在 API 层被拒（403），而非仅前端不展示。

## 3. 数据模型（核心）

| 实体 | 关键字段 |
| ---- | ---- |
| `document` | id, name, category_id, product_id?, current_version, visibility(项目继承/全公司), deleted_at?, created_by |
| `document_version` | document_id, version, file_key(MinIO), sha256, size, change_note?, uploaded_by, uploaded_at |
| `category` | id, parent_id, name, is_fixed(7个顶级) |
| `tag` / `document_tag` | 标签与文档多对多 |
| `project_document` | project_id, document_id（多对多关联） |
| `kb_revision` | kb_version(递增), affected_document_ids, applied_at —— RAG ingestion 变更记录，供审计引用 |

## 4. API 概要

```
POST   /api/v1/documents                 # 上传（multipart，支持批量）
POST   /api/v1/documents/{id}/versions   # 上传新版本
GET    /api/v1/documents                 # 列表（筛选/分页）
GET    /api/v1/documents/search?q=       # 全文搜索
GET    /api/v1/documents/{id}            # 详情（含版本历史）
DELETE /api/v1/documents/{id}            # 软删除
GET    /api/v1/projects/{id}/recommendations  # AI 推荐
```

## 5. 横切接入（F10）

- **审计**：`document.uploaded / version.created / deleted / acl.changed`。
- **权限**：F2.6 是 RBAC 文档权限继承的落地点；分类树管理与角色挂钩（AI管理员）。
- **KPI**：无独立 KPI；`kb_revision` 是 F10.3 审计中"知识库版本"字段的来源。

## 6. 非目标

在线协同编辑、文档审批流、全文 OCR 缓存策略优化、跨库联邦检索 [PHASE1_SPEC §4]。

## 7. 开放问题

- **Q1** 中文分词方案（pg 内 zhparser/jieba 自定义词典）与初始标签体系（是否预置标签集）。
- **Q2** 被引用文档是否允许删除，还是仅允许"下架（不再参与检索）"。
- **Q3** 文档存储去重策略：相同 SHA-256 是否共享物理文件（建议是，逻辑多副本）。
- **Q4** 历史版本是否参与 RAG 检索（默认仅最新版，见 F3 Q2）。
