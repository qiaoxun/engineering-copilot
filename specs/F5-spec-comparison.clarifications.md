## Clarifications

- Q1: 安全/关键参数清单与分级规则表由业务专家提供初版 → 决策：初版分级规则表不等待客户提供——由我方基于电池行业通用标准（GB 38031、IEC 62660 等）起草：安全相关参数（绝缘/耐压/防爆/温度极限等）≥30 项 → 🔴，关键性能（容量/内阻/循环寿命/倍率等）≥40 项 → 🟠，其余默认 🟡；以 DRAFT 态导入可配置规则表（FR5.3.1），由客户方研发主管（电池领域专家，同 F1 参数字典、F10 定版权限持有者）评审确认后置 APPROVED 方在线上生效（测试环境可整库启用）；后续增改走规则表 CRUD + 审计事件 `levelrule.updated`（对齐 `<domain>.<verb>` 命名），分级结果仍按 FR5.3.2/FR5.3.3 支持人工逐行覆盖并入审计 `level.overridden`。理由：分级规则表是 FR5.3.1 的规则基准，其质量责任属研发质量线，复用平台 DRAFT→APPROVED 状态机避免另造审批流，同时不阻塞 M3 开发启动（与 specs/README.md「开放问题不阻塞开发启动」约定一致）。（影响 FR5.3.1、FR5.3.2、FR5.3.3；关联 F10 DRAFT→APPROVED 与审计命名规范）
- Q2: 差异召回率验收目标值与标注集规模 → 决策：维持 AC5.1.1 目标差异召回率 ≥95%（初版目标，M3 验收硬门槛），标注集定义为 3 组真实规格书对（6 份文档，A/B 各含同模板对 ≥1 组、跨模板对 ≥2 组），由 ≥2 名电池工程师按统一标注模板双人独立标注 + 分歧仲裁（同 F1 金标集流程），每组对标注字段级差异 ≥60 条、总计 ≥180 条；召回率口径 = 正确对齐并输出的差异行数 / 标注差异总数，其中跨模板组的「对齐」以人工确认映射（FR5.2.2）后的结果计——未确认映射导致的漏配不计入系统召回失败，但映射建议的召回率（建议含标注真值映射的比例 ≥90%）单独统计作为 F5.2 观测指标（不作为硬门槛）；同时记录精确率与 AI 建议等级采纳率作为观测指标，不设硬门槛。理由：AC5.1.1 原文已定 ≥95% 与 3 组规模，本决策补充可复现的标注与统计口径，使 M3 验收（文档比对时间 ↓80%，PRD §50）可与质量指标同基线评测；跨模板召回依赖人工确认映射，故按确认后口径测量才与 FR5.2.2「未经确认不参与最终 Diff 结论」一致。（影响 FR5.1.1–FR5.1.3、FR5.2.1、FR5.2.2、AC5.1.1）
- Q3: 映射库 scope 粒度：Phase 1 先 global + 手动模板族，是否需要按客户/产品线自动分域 → 决策：Phase 1 仅实现 `scope ∈ {global, template_family}`（global 为默认，template_family 由用户发起对比时手动选择/标注模板族），**不做**按客户/产品线自动分域；`field_mapping.scope` 字段定义为可扩展枚举，未来若多客户共享部署需增加 `customer`/`product_line` 枚举值时仅改字典不改表结构。理由：PRD §46.4 将本平台定位为私有化第一阶段交付，单客户私有化部署下数据天然隔离，自动分域无数据与场景支撑，且 Phase 1 映射库初始为空（FR5.6.2）、条目量小，手动模板族已满足 AC5.2.1「同模板族第二次对比自动生效」；预留枚举扩展保证零迁移。（影响 FR5.2.3、FR5.2.4、FR5.6.1、FR5.6.2、AC5.2.1）

## Assumptions

- Q1 规则表 APPROVED 前的默认行为：线上运行遇未定版规则表时按「全部 🟡 + LLM 建议」兜底分级，不阻塞对比任务执行（与 F1 字典「测试环境可整库启用」同语义，仅约束线上生效判断，不影响开发/测试环境）。
- Q2 标注人力与节奏依赖客户方配合；若客户方标注资源延迟，M3 允许先以我方自建标注集（3 组对、≥180 条差异，双人标注）做内部验收，客户方标注集就绪后复测作为正式验收（同 F1 golden_set_v1 的处理方式）。
- Q2 的 3 组规格书对优先从 F1 金标集（golden_set_v1，≥35 份）中选取，复用其已确认的解析结果与人工校对产出，降低标注成本。
- Q3 映射库为部署域内全局共享（`field_mapping` 无 project_id 字段，与 spec §3 数据模型一致）；模板族（template_family）标签由用户手动填写/下拉选择（建议值来源：F1 解析元数据中的模板识别结果），Phase 1 不做模板族自动聚类。
