## Clarifications

- Q1: 判定标准的机器可执行表达（阈值型/区间型/布尔型），影响自动判定覆盖率，需与 F8 联合设计 → 决策：**在 `test_case` 上增加结构化判定标准字段 `criteria`（JSONB，F8 侧生成/采用时结构化落库，F9 只消费不改写）**，Phase 1 支持三型：① 阈值型 `{type:"threshold", metric, op: gte|gt|lte|lt, limit, unit}`（如容量 ≥ 100 Ah）；② 区间型 `{type:"range", metric, min, max, min_inclusive, max_inclusive, unit}`（如内阻 0.8–1.2 mΩ）；③ 布尔型 `{type:"boolean", expected: true}`（目视/功能性检查，导入时判定列直填 Pass/Fail，系统不再计算）。一条用例可挂多条 criteria，**全部通过才 Pass（AND 语义）**；自动判定为确定性规则引擎（非 AI，不走 LLM），判定优先级：导入文件判定列人工直填 > 结构化 criteria 自动判定 > pending。兜底路径：用例仅有自由文本判定标准（无结构化 criteria）时，导入任务内做一次**确定性抽取**（正则解析文本中的数值限值 + 单位对齐，仅覆盖阈值/区间数字型；此抽取不产生 AI 审计负担，抽取规则版本化记录于 `test_data_import.warnings`），抽取失败该行置 `pending`「待人工判定」并进入行级警告列表，不阻塞其余行入库。超限幅度（FR9.3.1）计算：阈值型 `(|实测−limit|/limit)×100%`，区间型取偏离最近边界的同式幅度，与 UI 页面21「超出判定阈值 12%」口径一致。自动判定覆盖率 = 自动判定行数 / 总行数（排除人工直填），作为报告「数据统计」节（FR9.2.3）固定统计口径的一部分输出。理由：F8 FR8.3.4 已要求判定标准尽量携带量化阈值并定位原文，结构化字段是该要求的自然延伸，F8 产出侧一次结构化、F9 消费侧零猜测，避免在 F9 重复做自然语言理解；三型枚举覆盖 PRD §31 判定标准的全部常见形态且规则可单测（AC9.3.1 可用预置答案直接校验）；自由文本兜底走确定性正则而非 LM 判定，保证判定结果可复现、可审计，符合 PRD §43「测试结论必须人工确认」的保守取向——判不了的显式交人工而非让 AI 猜。（影响 FR9.1.3、FR9.3.1、AC9.3.1、FR9.2.3、§3 数据模型（`test_result_row` 判定来源字段）；关联 F8 FR8.3.4、§3 数据模型（`test_case` 增 `criteria` 列））
- Q2: 报告 Word 模板是否使用企业现有模板（版式由实施期配置） → 决策：**Phase 1 不绑定企业现有模板——平台内置一套默认 docxtpl 模板（章节即 FR9.4.1 八节：概要/测试范围/数据统计/图表/Pass-Fail 明细/异常项分析/结论/附件清单），同时把「模板文件」做成实施期配置项**：部署实施时可在平台设置中上传替换企业自有 docxtpl 模板（模板文件版本化留存，替换写审计 `report.template.updated`），占位符契约（`{{stats.*}}`、`{{charts.*}}`、`{{anomalies.*}}`、`{{conclusion}}` 等变量名与类型）作为文档化契约固定不变——正文 JSON（§3 `test_report.body`）与模板解耦，换模板只改版式不改数据与 API。图表以预渲染 PNG 占位符注入 Word/PDF；默认模板与 PDF/Word 双格式共用同一数据装配层。企业模板深度适配（复杂页眉页脚/骑缝章/质量体系受控文件标识）列入实施期服务项，不阻塞 M4 开发。理由：PRD §32 只约束章节内容不约束版式，FR9.4.1 已指定 docxtpl 技术路线，模板可替换是该路线的零成本副产品；Phase 1 私有化首期拿不到企业受控模板的稳定样例（与 F8 Q4 编号体系同因），先以内置默认模板保证 KPI（报告制作时间 ↓70%）可验收，docxtpl 占位符契约冻结使企业模板接入成为纯配置工作、无代码改动，与 F7（FMEA Excel/Word 标准排版）同类导出先例一致。（影响 FR9.4.1、FR9.5.1；关联 F10 审计、F7 FR7.6.1 先例）
- Q3: 报告编号规则（RB-项目-年份-序号？）是否对齐企业质量体系文件编号 → 决策：**Phase 1 采用 `RB-{项目代号}-{年份}-{序号}`，序号为项目内按年递增、3 位零填充（`RB-XXX-2026-001`，超 999 自然进位）**；编号在报告草稿创建（`POST /test-reports/drafts`）时即分配并终身不变（含状态流转与重导出），变更项目代号不回溯改写已有报告编号。不与企业质量体系文件编号做自动兼容映射，但 `test_report` 增加 `external_report_no`（可空）字段供人工录入企业受控编号，列表/详情/导出（FR9.5.1）与 F9.6 生成的问题单/FMEA 引用在 `external_report_no` 非空时优先展示（`RB` 号作为系统主标识不变）；企业编号规则自动对接列入 Phase 2（与 F8 Q4、§6 非目标「TCM/试验管理系统对接」同批），实施期可通过配置项调整前缀字面量（如企业要求 `QR-` 开头），但结构不开放为完全自定义模板。理由：与 F8 Q4 已裁定的 Case ID 策略保持同一模式（自有规则为主键语义 + external 列映射），避免同一平台两套编号哲学；企业质量体系编号规则各异且依赖其受控文件管理程序，首期无法保证拿到且稳定，「可对应」而非「可兼容」即可满足审计追溯（F10）要求；草稿创建即分配编号保证导出记录、FMEA 行引用（FR9.6.1 附报告引用）、Issue 关联（FR9.6.2）指向的编号终身稳定，避免 APPROVED 后编号漂移破坏追溯链。（影响 FR9.5.1、FR9.4.3、FR9.6.1、FR9.6.2、§3 数据模型（`test_report` 增 `report_no`/`external_report_no` 列）；关联 F8 clarifications Q4、F10 审计追溯）

## Assumptions

- Q1 导入文件判定列已填值的行：系统不做自动判定、不覆盖人工判定（人工直填优先），但若直填值与结构化 criteria 自动判定结果冲突，该行进警告列表提示「人工判定与判定标准不一致」供复核（复核动作写审计 `anomaly.verdict.reviewed`），不阻塞导入。
- Q1 区间型开闭边界默认闭区间（min/max 均含），`min_inclusive/max_inclusive` 显式为 false 时按开区间；实测值单位与 criteria `unit` 不一致时不做自动换算，按单位不匹配置 pending 并入警告列表（避免单位换算引入错误判定）。
- Q1 criteria 抽取/自动判定规则引擎版本化（`criteria_engine_version` 记录于 `test_data_import`），引擎升级不回溯重判历史报告；已 APPROVED 报告的判定结果不可被重判覆盖。
- Q2 报告中 [AI] 内容（AI 整改建议 FR9.3.2、AI 结论草稿 FR9.4.2）在导出物中带「AI 生成，已经人工确认」脚注标识（APPROVED 后）或「AI 草稿」标识（APPROVED 前，叠加 DRAFT 水印），满足 README「AI 输出 UI 必须带标识」在导出物上的延伸。
- Q2 模板替换仅影响后续新生成的报告渲染；已导出的历史文件（`file_key` 留存）不因模板变更重渲染，保证「导出记录：谁、何时、哪个版本」（FR9.5.1）可复现。
- Q3 报告编号在 `POST /test-reports/drafts` 事务内分配（项目内计数器），草稿删除后编号作废不回收（宁留空洞不重号，与 F8 Q4 号段策略一致）；`GET /api/v1/test-reports/{id}` 返回体含 `report_no` 与 `external_report_no`。
