## Clarifications

- Q1: 企业测试标准文档的形态（结构化标准 vs 扫描件），决定复用率与抽取难度，需尽早拿到样例 → 决策：**不等待样例、不做「企业测试标准」专用抽取器**——Phase 1 该类文档与规格书/客户需求同样统一经 F1.6 解析模型入库（PDF/Word/Excel 走结构化读取，扫描件/图片自动路由 F1.3 OCR 通道、低置信度块标红），按 F2 知识库文档管理；生成侧将其作为检索上下文（切片引用，复用 `object_source_link` 定位原文），判定标准量化阈值（FR8.3.4）优先从其 Fields/表格参数取值。样例到位后的适配仅发生在 F1 解析层（模板识别/参数字典），不改动 F8 数据模型与 API。交付策略上优先引导客户提供电子版（Word/Excel/原生 PDF）测试标准，扫描件仅作兼容路径；扫描件比例与 OCR 置信度分布记入 `generation_run.inputs` 元数据，作为复用率/抽取质量的观测基线。理由：FR8.1.1 已限定四类资料「均来自当前项目关联文档」，即天然走 F1.6 统一入口（specs/README.md 数据契约：下游禁止绕过），为 F8 另建标准文档解析通道既违反契约又无样例支撑；F1 金标集已含扫描件（≥5 份），OCR 兜底能力在 M1 已验收，风险可控且不阻塞 M4 开发启动。（影响 FR8.1.1、FR8.2.2、FR8.3.4；关联 F1.6/F1.3、F2、specs/README.md 数据契约）
- Q2: 复用判定相似度阈值初值与复用误判（误复用）的兜底提示方式 → 决策：阈值初值 **0.90**（向量余弦相似度，embedding 与平台检索统一模型），并加一道确定性预筛：候选须在「测试项目 + 判定标准」关键词级粗匹配命中方可进入相似度计算（防止语义近似但测试对象/条件不同的误复用）；阈值作为平台配置项 `testgen.reuse.threshold`，M4 验收时以 AC8.4.1 金标场景（重复项目生成）实测校准。兜底方式：**复用标记仅为提示性标注，永不自动采用**——复用项与新增项同样进入 DRAFT 态逐条人工处置（FR8.5），处置卡片展示来源用例链接 + 相似度分数，并固定提示「复用为系统建议，请核对测试条件与判定标准是否适用于本项目」；相似度落在 `[阈值−0.05, 阈值)` 的边界带条目标记「疑似复用」供参考，但不计入复用统计（避免抬高复用率）；误采用后仍可经 FR8.5.2 编辑修正并留 diff 审计。理由：0.90 高阈值 + 关键词预筛是「宁漏判为新增、不错标复用」的保守取向——误复用的代价（沿用不适用判定标准）高于把复用误报为新增（人工多看一条），且 spec 本就要求逐条人工处置（FR8.5.1），标注错误的最终兜底是人工而非算法；阈值配置项化与 F5/F6/F7 先例（分级规则、RPN 阈值、行数上限）一致。（影响 FR8.4.1、FR8.4.2、AC8.4.1、FR8.5.1、FR8.5.2；关联 F10 审计）
- Q3: 覆盖率口径需与质量部对齐（是否按需求类型加权）→ 决策：Phase 1 采用 spec §5 已写口径并明确细化——`覆盖率 = 有≥1条已采用用例的需求数 / 已采用需求总数`，**不加权**：分母为 status=ADOPTED 的测试需求（排除 DRAFT/IGNORED），分子为其中 requirement_ids 上挂有 ≥1 条 status=ADOPTED 用例的需求（FR8.3.3 挂接关系为统计基础）；`GET /api/v1/projects/{id}/test-coverage` 返回分子/分母/覆盖率及按需求的明细列表，可下钻到未覆盖需求清单。权重机制不实现但预留：统计实现读取配置 `testgen.coverage.weights`（默认全 1），质量部后续若要求按需求类型（如安全类）加权，仅改权重配置与统计计算，不改数据模型与挂接关系；与质量部的口径对齐列入上线前验收流程项（非开发阻塞项）。理由：spec §5 已给出「有≥1条已采用用例的需求 / 已采用需求总数」的等价比率，未加权口径可由现有数据模型（test_requirement.status + test_case.requirement_ids）直接推导，M4 即可交付「覆盖率可统计」验收（PHASE1_FEATURES F8 整体验收）；加权依赖需求类型主数据（Phase 1 无分类体系对接），先落地简单口径、预留权重配置是零迁移的演进路径。（影响 FR8.3.3、§5 KPI 小节、`GET /test-coverage`；关联 PHASE1_FEATURES F8 验收）
- Q4: Case ID 号段规则是否需要与企业既有编号体系兼容 → 决策：Phase 1 采用 spec 规则 `TC-{项目代号}-{序号}`，序号为**项目内**递增、3 位零填充（`TC-XXX-001`，超 999 自然进位）；号段预占机制：发起生成任务时按预估产出条数 +20% 缓冲预占号段（记录于 `generation_run`），任务失败或用例被忽略/删除后号段**作废不回收**（宁留空洞不重号）；不与企业既有编号体系做双向兼容映射，但 `test_case` 增加 `external_case_no`（可空）字段供人工录入企业编号，列表/详情/导出与 F9 测试报告在 `external_case_no` 非空时优先展示（TC 号作为系统主键不变）。企业编号体系自动对接列入 Phase 2（与 §6 非目标「TCM/试验管理系统对接」同批）。理由：企业既有编号规则各异且依赖其质量体系文件，Phase 1 私有化首期拿到规则也无法保证稳定，主键用自有规则 + `external_case_no` 映射列即可满足「可对应」而不承担「可兼容」；号段预占在 F4.5 异步任务模型内实现（run 创建时预占，无需分布式锁），作废不回收的策略保证 AC8.6.1 场景下 Case ID 终身唯一，避免归档入历史用例库（FR8.6.3）后出现跨项目溯源歧义。（影响 FR8.3.2、§3 数据模型（`test_case` 增列）、FR8.6.3；关联 F9.1.1 Case ID 导入校验、§6 非目标）

## Assumptions

- Q1 「企业测试标准」的库内组织与规格书/客户需求一致（同一文档表 + F2 分类标签），Phase 1 不引入「标准条款树」结构；若样例显示客户标准为高度表格化的限值表（参数/限值/试验方法三列式），在 F1 参数字典中补充对应字段映射即可，属 F1 层适配。
- Q1 OCR 通道产出的低置信度片段被生成任务引用为依据时，依据卡片沿用 F1 标红语义提示「来源为扫描件 OCR，请对照原文核验」，不阻断生成。
- Q2 相似度计算在生成任务完成阶段异步批量执行（不阻塞 SSE 进度流），复用标记随结果一并返回；历史用例库为空时（首次使用）全部标「新增」，统计卡正常输出 `新增 N / 复用 0`。
- Q2 疑似复用边界带宽度（0.05）与阈值同为配置项；两个项目各自生成的用例互不影响，复用判定只对历史用例库（FR8.6.3 归档）+ 本项目已采用用例进行。
- Q3 覆盖率统计仅统计 ADOPTED 态对象（AI 语义 `adopted` 与平台 `APPROVED` 定版在本 feature 内同义，处置即定版，符合 F10.2「任何 API 不允许 AI 输出直接 APPROVED」——处置动作必须是人工触发）。
- Q4 项目代号（`TC-` 后段）取项目创建时的短代号（大写字母/数字，≤10 字符），由项目设置维护；项目代号变更不回溯改写已生成 Case ID（ID 快照固化），仅影响新号段。
