## Clarifications

- Q1: S/O/D 评分标准表初稿与五维链生成质量评测集的来源 → 决策：两者均不等待业务专家到位，由我方先行起草——(a) 评分标准表：按 FR7.2.2 的 1–10 语义分档内置一套默认 `sod_rubric` 初版（S 按失效影响的严重度语义：安全/法规风险→9–10、功能丧失→7–8、性能降级→5–6、可感知轻微缺陷→3–4、不可感知→1–2；O 按历史案例发生频次统计分档；D 按现有控制措施的可探测性分档：无探测手段→9–10 … 自动化在线检测→1–2），以 DRAFT 态入库（沿用 `sod_rubric` 配置表，挂在平台域），由客户方研发/质量专家（同 F10.5 定版权限持有者）评审后置 APPROVED 固化生效，测试环境可整表启用，评审通过前系统使用 DRAFT 初版打分（见 Assumptions 兜底）；增改走 rubric 维护接口并记录审计事件 `sod.rubric.updated`（对齐 `<domain>.<verb>`）。(b) 评测集：从历史项目中选 3 个规格书齐全、有历史 FMEA 的项目（电池包级 1 个 + 子系统级 2 个）构建金标评测集——我方工程团队先按五维链 Schema 标注 ≥10 行/项目的金标行，经客户方 FMEA 工程师人工确认后固化（评测集为测试资产，不入线上库，不占用 DRAFT→APPROVED 状态机），用于 AC7.1.1 的维度语义正确性走查与后续 prompt/模型版本回归。理由：与 F5/F6 Q1 同构——rubric 是 FR7.2.1 打分建议的数据基准，复用平台 DRAFT→APPROVED 避免另造审批流；评测集是 AC7.1.1 的可执行验收前提，自建金标 + 人工确认是 PRD §43「AI 自检→规则校验→人工审核」链路的验收侧对应物，且两者均不阻塞 M4 开发启动（specs/README.md 约定）。（影响 FR7.2.1、FR7.2.2、AC7.1.1；关联 F10.2 DRAFT→APPROVED、F10.3 审计）
- Q2: 风险色标阈值采用 VDA-SSR 还是 AIAG-VDA FMEA 手册标准 → 决策：Phase 1 采用 **AIAG-VDA FMEA 手册（经典 RPN 体系）**：`RPN = S × O × D`（1–1000），色标阈值按 FR7.2.3 默认 红 ≥100 / 橙 50–99 / 绿 <50，阈值作为平台配置项可按项目调整。理由：spec 的数据模型与 API 全部围绕 S/O/D 数值列 + RPN 实时计算构建（`fmea_row.s/o/d/rpn`、UI 页面16 的 S/O/D/RPN 列、FR7.2.3 的乘法公式与默认阈值即 AIAG RPN 口径），而 VDA-SSR 用 A/P 两个维度 + Action Priority（H/M/L）查表替代 RPN，需要更换列结构、评分维度与色标语义，属结构性改动——与 spec 原文的「FR7.2.3 RPN = S×O×D」直接冲突，Phase 1 不采纳；VDA-SSR / AP（Action Priority）支持列入 Phase 2（可作为 rubric 配置的可选打分模型扩展，不改变既有数据模型）。选择 AIAG-VDA 还因其在国内动力电池行业既有历史 FMEA 中最常见，历史案例打分统计（FR7.2.1 的 O 值依据）可直接复用。（影响 FR7.2.1、FR7.2.3；§6 非目标补充：VDA-SSR/AP 列为 Phase 2 非目标，不修改 spec 原文）
- Q3: 单个 FMEA 的行数上限（防 token 失控）→ 决策：采纳 spec 建议——单次生成任务输出上限 **50 行**（AI 初稿 ≤50 行），后端硬校验：LLM 结构化输出经 FR7.1.2 自检后若 >50 行，按 seq 截断至 50 并在任务完成事件中提示「已达单次生成上限 50 行，可缩小范围（填写 FMEA 范围说明）或按功能子系统分区域多次生成」；单个 FMEA 版本（一个 revision）累计行数上限 **200 行**（多批次生成/人工增行的合计），达到上限后增行接口（`POST /rows/batch`）返回统一错误体 `FMEA_ROW_LIMIT_EXCEEDED`；两个阈值均为平台配置项（`fmea.generate.row_limit` / `fmea.total.row_limit`）。理由：50 行/次与主流 LLM 单次结构化输出可靠上限匹配（50 行 × 五维 + 引用 ≈ 数万 token），且 AC7.1.1 的 ≥10 行金标在限内；200 行累计上限覆盖电池包整包级 FMEA 的真实规模（典型 100–300 行），超限时引导分区域而非静默失败，与 FR7.1.1 可选 scope_note 的设计自洽；分区域多次生成天然落在 F4.5 异步任务模型内，无需新机制。（影响 FR7.1.1、FR7.1.2、FR7.1.4、FR7.4.1；关联 F4.5 异步任务、统一错误体）

## Assumptions

- Q1 DRAFT rubric 的兜底语义：客户专家评审（APPROVED）生效前，AI 打分建议使用 DRAFT 初版 rubric，行级打分理由中注明「依据未定版评分标准」；rubric 生效仅影响**新生成**任务与未打分行，已定版（APPROVED）的 FMEA 不重算（分值随行快照固化）。
- Q1 评测集 3 个项目的选取标准：有完整规格书（F1.6 解析通过）+ 历史定版 FMEA；若客户无法提供 3 个，降级为 2 个项目 + 1 个公开行业案例，验收口径（AC7.1.1 ≥10 行/场景）不变。
- Q2 FR7.2.3 阈值（红/橙/绿）与列结构按 AIAG RPN 实现后，「对齐 VDA/AIAG」中的 VDA 指历史案例中的既有打分口径可导入，不引入 VDA-SSR 的 A/P 列。
- Q3 单次生成截断为确定性规则（按 LLM 返回的 seq 顺序保留前 50 条有效行），不额外调用 LLM 复核；人工增行计入 200 行累计上限，删行释放配额。
